ℹ️ How detection works & limitations

What the browser can and can't tell us

1️⃣ First the engine tries a readable fetch. If the server allows it, the HTML is scanned for filter signatures (Lightspeed, relay.school, lsfilter, ls-block, "blocked"/"restricted" notices, etc.) → verdict is verified ✅/🚫.
2️⃣ Cross-origin pages usually can't be read (same-origin policy), so it falls back to opaque fetch, hidden <iframe>, <img> favicon and <script> probes, using load/error/timing signals. Those verdicts are labeled inferred in Details.
3️⃣ If this page is served over HTTPS (e.g. Netlify), browsers block http:// targets as mixed content — those show ⚠️ with a hint. For full coverage, run the file over plain HTTP (e.g. python -m http.server) or allow insecure content for the site.
4️⃣ A "Blocked (suspected)" can also mean the site just forbids framing (X-Frame-Options) — treat inferred verdicts as leads, not proof.
5️⃣ The DNS-over-HTTPS pre-check (Google/Cloudflare — configurable in Scan Settings) verifies that wildcard-DNS names like 1.2.3.4.nip.io actually resolve to your target IP and fails fast on NXDOMAIN instead of burning probe timeouts.
6️⃣ Click any results row to open its per-probe evidence log — every probe tried, its result, timing, and whether the final verdict was verified or inferred. Export CSV includes this probe log.

Responsible use: run this only against hosts/networks you own or are authorized to test. Circumventing an organization's filtering policy may violate acceptable-use rules.
